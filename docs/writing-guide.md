# Writing guide

Use ASD-STE-100 as the reference for clear technical English. These project
rules apply its main writing principles. They do not establish full compliance
with an ASD-STE-100 issue or an approved-word dictionary.

## Write for the task

- State the purpose before the procedure.
- Use active voice.
- Use short sentences. Aim for no more than 20 words in instructions.
- Put one instruction in each numbered step.
- Start an instruction with a verb, such as **Open**, **Select**, or **Copy**.
- Put a condition before the action it controls.
- Use the same term for the same item.
- Keep interface labels and code identifiers exact.
- Explain an unfamiliar technical term when it first appears.
- Use a table when readers need to compare parallel choices.

Use separate paragraphs for different topics. Keep warnings beside the action
that needs them. State the consequence and the action the reader must take.

## Use consistent terms

| Term | Meaning |
| --- | --- |
| Road profile | The ordered components in a road cross-section |
| Road segment | A placed section of road |
| Junction | A connection that shares topology between roads |
| Roundabout | A circulating ring with connected approaches |
| Superelevation | Road banking on a curve |
| Place | The Roblox document containing world data |
| Plugin settings | Preferences and presets saved by the plugin |
| Asset | An imported model used by a road or structure |

Preserve the spelling in interface labels. For example, use **Regional
Preference** when you refer to that dock. Use `RoadProfile` when you refer to
the source module.

## State evidence accurately

- Distinguish current behavior from planned work.
- Name the build or commit when a result depends on a version.
- State what a check measures and what it cannot establish.
- Do not claim Studio testing when only Python checks ran.
- Do not promise dates, support levels, or compatibility without evidence.
- Do not describe a private preparation build as a published release.

## Review a document

1. Check each command against the current tool.
2. Check each interface label against the current source or interface.
3. Check local links and file paths.
4. Remove placeholders that the reader cannot resolve.
5. Check the license name and status.
6. Read each procedure in order.
7. Check sentence length and technical terms.

A formal ASD-STE-100 conformance review requires the applicable standard and
dictionary. Record that review separately if the project completes one.
